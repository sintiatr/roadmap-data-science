§8 — AFTER THE SPRINT

Career Playbook: Turning 30 Days Into Interviews

The tools and certifications get you in the room. These five moves are what actually get you a callback.

01 · RESUME

Lead every bullet with the business result, not the tool: "Cut churn analysis time from 3 days to 2 hours using SQL + Python" beats "Proficient in SQL and Python." Quantify wherever the case studies above give you a number.

02 · PORTFOLIO LINKS

Put your GitHub and Tableau Public profile links directly under your name on the resume header — not buried at the bottom. Recruiters spend under 10 seconds per resume; make the proof impossible to miss.

03 · INTERVIEW PITCH

For each of the 5 case studies above, rehearse the "Interview Pitch Guide" line in its modal out loud until it's under 45 seconds. That's your answer to "walk me through a project."

04 · SQL SCREENING

Most first-round screens are live SQL. Spend the week before applying doing timed StrataScratch / DataLemur sessions (25 min, no notes) — speed under pressure is what's actually being tested, not knowledge.

05 · NETWORK LOOP

Post one dashboard or notebook per week on LinkedIn with the business problem in the caption, not just a screenshot. This is what most self-taught hires say actually generated inbound recruiter messages.

Realistic timeline

30 days builds working proficiency, not mastery. Most self-taught career-switchers report 3–5 months from "starting SQL" to a signed offer, including this sprint, ~4–6 weeks of applications, and 2–3 rounds of interview prep per employer. Treat Day 30 as launch day for the job search, not the finish line.

Where to find real job postings

Search titles "Data Analyst," "Business Intelligence Analyst," and "Reporting Analyst" — they overlap heavily and are the most common entry points. LinkedIn's "Easy Apply" filter plus a saved search alert on Indeed for these three titles covers most of the entry-level market.

§9 — SPEED UPGRADES

Modern Toolkit: Faster Than the 2020 Default

Learn pandas and core SQL first — the fundamentals above don't change. Once they're solid, these swap in for real speed and less boilerplate on the same work.

Polars Replaces pandas

Rust-built DataFrame engine on Apache Arrow. Routinely 5–30x faster than pandas on groupby, sort, and joins, with 30–60% less memory — and lazy execution that optimizes your whole query before running it.

pola.rs →
DuckDB SQL, zero ETL

An in-process analytical SQL engine — query CSV, Parquet, or JSON files directly with plain SQL, no server or import step. Pair it with Polars for a local data warehouse on your own laptop.

duckdb.org →
ydata-profiling Auto-EDA

Generates a full exploratory report — distributions, correlations, missing values, warnings — from a single line of code. Turns a 2-hour manual EDA notebook into a 2-minute first pass.

GitHub →
PyGWalker Visual EDA

Turns any pandas or Polars DataFrame into a Tableau-style drag-and-drop UI inside a Jupyter notebook — good for fast visual exploration before you write a single chart line.

GitHub →
Marimo Notebook

A reactive Python notebook stored as a plain .py file — no hidden execution-order state, real git diffs, and it deploys as a shareable app. Fixes the biggest pain points of classic Jupyter.

marimo.io →
Power Query + DAX quick measures Excel/BI side

Don't sleep on the non-Python speedups: Power Query's "Fill Down" / "Unpivot Columns" and Power BI's auto-generated quick measures replace what used to be manual formula-writing for common cleaning and time-intelligence tasks.

Microsoft Learn →
Sequencing note — interviewers still ask pandas and core SQL, so learn those first (Days 1–14 above cover exactly that). Treat everything in this section as a Day 31+ upgrade once you're comfortable, not a shortcut around the fundamentals.
§10 — WORKING WITH AN LLM

LLM-Assisted Analysis

An LLM writes the first draft of a query or a chart faster than you can — but it doesn't know your schema's quirks or whether a number is actually right. Use it to accelerate, not to skip verification.

Claude / ChatGPT — SQL & reasoning Design

Paste your schema (or a `CREATE TABLE` statement) into a chat and describe the question in plain English — "compute Q3 cohort retention by signup month." Good for reasoning through the right join or window function before you write it.

Cursor / Claude Code — in-editor Execute

AI-native editors for the SQL or Python files you're already writing. Inline edits let you describe a change ("group by month, not week") instead of retyping the query, and tab-completion speeds up repetitive joins and pandas chains.

Code Interpreter / Claude with files Explore

Drop in a CSV or Excel file and ask "what's interesting in this data?" for a fast first-pass EDA — summary stats, plots, and anomaly flags — before you commit to a manual notebook.

PandasAI Explore

Open-source Python library that lets you query a pandas/Polars DataFrame, SQL database, or Parquet file in plain English and get an answer or chart back — useful for quick, conversational exploration inside your own scripts.

GitHub →
AI-native notebooks Team workflow

Hex, Deepnote, and Mode now build AI directly into the notebook — connect your warehouse, get suggested queries, and generate a first chart from a natural-language prompt without leaving the notebook.

Copilot for BI tools Power BI / Tableau

Power BI's Copilot and Tableau's built-in AI assistant can draft a first DAX measure or LOD expression from a plain-English description — a faster starting point than a blank formula bar, still worth checking against SQLBI/Tableau docs.

Verify before you ship — an LLM can silently misread a schema, join on the wrong key, or invent a plausible-looking number. Always read the generated SQL, spot-check the output against a known total, and never paste an answer straight from a chat into a client-facing dashboard without independently confirming it.
